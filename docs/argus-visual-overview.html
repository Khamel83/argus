Argus is a private retrieval authority for AI agents. This map is its operator surface: a route from a practical symptom to a source of truth, a bounded next action, and a verification gate.

01 · Access & evidence

One authority keeps the evidence coherent.

Production callers delegate through private authenticated ingress. They carry intent and scoped access; the authority owns execution policy, durable state, and the retrieval capabilities that create evidence.

Caller surfaces

Native MCP, HTTP, and CLI

Interactive agents use native MCP. Services use HTTP. Operators use CLI. None becomes a second broker.

→

Private authority

Authenticated execution

Routing policy, sessions, provider credentials, persistence, browser capability, and budgets remain authority-owned.

→

Evidence out

Search, extraction, and provenance

Ranked results and readable content carry provider, egress, machine, and source-path context for downstream review.

02 · Status semantics

“Up” is not one thing.

Use the status layer that answers the question. Process liveness, cached dependency readiness, and the operator view prove different things; provider configuration is not provider health.

First question

Liveness

Can the event loop answer at all? This is not a broker, database, provider, browser, or network check.

Promotion question

Readiness

Are required dependencies currently classified as ready enough to serve? A degraded result can still be ready.

Diagnosis question

Operator status

Which capability, observation, schema, provider, or runtime fact explains the condition?

State

Healthy

Current evidence supports the expected capability. Treat it as a current observation, not a permanent guarantee.

State

Degraded

Useful service remains, but an evidence gap or impaired capability needs attention before it becomes an outage.

State

Unready

A required authority dependency is missing or failed. Do not promote or call this a successful retrieval system.

State

Unknown

Evidence is absent or stale. Configuration must not be used to invent reachability or health.

State

Disabled

The capability is deliberately out of service. It is not an implicit recovery target or silent fallback.

03 · Symptom guide

Choose a probe before a fix.

The right first check should cheaply distinguish a caller problem from an authority problem. These branches deliberately start with read-only evidence and name the team surface that owns the next action.

Symptom · connection or certificate error

Start with the caller route.

Transport cannot establish the private listener identity. This is not yet evidence of a provider failure.

Safe check
Confirm the caller uses the canonical private ingress rather than a loopback or raw-network substitute.
Owner
Client routing and private ingress.
Source
MCP client setup

Symptom · MCP returns 401

Ingress answered; authorization did not.

An authentication rejection proves the route reached the listener. Diagnose scoped caller access before touching retrieval execution.

Safe check
Inspect the caller's credential presence and scope without printing its value.
Owner
Client configuration and authority access policy.
Source
MCP client setup

Symptom · liveness succeeds, retrieval fails

Process evidence is too shallow.

The event loop can reply while dependencies or retrieval paths are impaired. Move from liveness to readiness, then detailed status.

Safe check
Compare readiness with the operator status before restarting anything.
Owner
Authority dependencies and runtime operations.
Source
Operations

Symptom · provider or extraction fails

Configuration is not condition.

A configured path may be unreachable, cooling down, out of balance, missing a browser capability, or blocked by a target.

Safe check
Inspect capability, reachability, health, cooldown, balance, and provenance as separate signals.
Owner
Broker, extraction chain, and provider policy.
Source
Operations Status

Symptom · ChatGPT cannot reach MCP

This is a human-gated boundary.

A cloud client is not a private-network peer. It needs the approved private-MCP tunnel association and the right platform permissions.

Safe check
Verify the tunnel association and required human permissions; do not expose the private listener.
Owner
Platform access and tunnel operator.
Source
MCP client setup

Symptom · development test is red

Separate baseline from incident.

A local failure may be a fixture or source-baseline issue rather than evidence that the running authority needs intervention.

Safe check
Reproduce on the accepted source baseline, then classify it before changing a service.
Owner
Development acceptance and release gates.
Source
Operations

04 · Improvement board

Make the next iteration falsifiable.

These are durable places Argus can become easier to operate. A planning state is intentionally not a delivery claim: it says whether the next safe step is a design decision, evidence collection, or a human authorization.

Pain

Evidence

05 · Hard boundaries

Not every unavailable path is broken.

Some paths deliberately require a person to authorize them. Others are retired architecture and must stay unavailable. Treating both as an outage creates unsafe recovery work.

Human-gated

ChatGPT private MCP access

Use the approved private-MCP tunnel and its platform authorization. The correct action is to satisfy the human and platform gate, not to publish the private authority.

Read the client boundary

Retired / external

Former authorities are not fallbacks.

Old Mac, cloud, and worker paths are historical context. Recovery means restoring the production authority or client route, not reviving an unapproved alternate execution plane.
